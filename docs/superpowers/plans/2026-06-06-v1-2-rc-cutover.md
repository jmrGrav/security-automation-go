```markdown
## v1.2.0-rc1 — Release Candidate

**Release Candidate for v1.2.0**. All pre-v1.2 hardening complete.

### Security Improvements

- **File-backed admin token (CF_SYNC_API_TOKEN_FILE):** Admin API tokens can
  now be delivered from a file. File takes strict precedence over the env var;
  missing or empty file fails startup immediately. Aligns CF_SYNC admin token
  handling with OpenAI/Anthropic/Gemini file-backed secret model. (`SEC-01` resolved)
- **CSRF coverage confirmed:** All 10 POST mutation handlers verified to call
  `validCSRF`. Routes: settings/password/change, logout, forensic, intelligence,
  all provider admin routes, cloudflare ban, AI explain.
- **Bootstrap password idempotency proven:** First-boot E2E test validates
  bcrypt hash written, no plaintext stored, restart is idempotent, original
  credential preserved across reboots.

### Operational Improvements

- **logrotate copytruncate:** Replaced SIGUSR1-based log rotation with
  `copytruncate`. Go apps do not handle SIGUSR1 for log reopening; copytruncate
  works without signal cooperation. (`OPS-02` resolved)
- **DynamicUser logging template:** `LogsDirectory=security-automation` added
  to the systemd unit. systemd now creates and owns `/var/log/security-automation`
  before ExecStart, eliminating permission failures under `DynamicUser=yes`.
  (`OPS-01` resolved)
- **Startup logging subsystem:** `internal/startuplog` package writes a
  structured startup diagnostic to `/var/log/security-automation/startup.log`.
  Captures config validation, bootstrap init, and first sync results before
  journald buffering kicks in. (`OPS-03` resolved)
- **Environment file support:** `EnvironmentFile=-/etc/security-automation/security-automation.env`
  in the systemd unit. Config precedence: defaults < YAML < env file < env vars.

### Configuration

- `CF_SYNC_API_TOKEN_FILE` — file path for admin API token (takes precedence
  over `CF_SYNC_API_TOKEN`).
- `SECURITY_AUTOMATION_INITIAL_ADMIN_PASSWORD` — initial admin password for
  first-boot bootstrap (ignored on subsequent starts).
- `SECURITY_AUTOMATION_BIND_ADDR`, `SECURITY_AUTOMATION_WEB_PORT` — UI bind
  address and port overrides.

### Tests Added

- `TestResolveAdminToken` (5 subtests) — file token precedence
- `TestNewAuthenticator/with_file_token` — daemon authenticator uses file token
- `TestFirstBootEndToEnd` — bcrypt, no plaintext, idempotency, restart safety
- `TestConfigPrecedenceLayerOrdering` — 3-layer override chain
- `TestMutationSurface_CSRFAndMethodEnforcement` — 10 POST routes, CSRF enforcement

### Documentation

- `docs/runbooks/FIRST_BOOT.md`: Added `CF_SYNC_API_TOKEN_FILE`
- `docs/security/SECURITY.md`: File-backed token documented
- `docs/runbooks/CUTOVER_RUNBOOK.md`: Service name corrected (`cf-sync.service`)
- `docs/operations/STARTUP_WARNINGS.md`: Verified accurate

### Validation

All validation gates green:
- `gofmt -l .` clean
- `go vet ./...` clean
- `go build ./...` clean
- `go test ./...` all PASS
- `go test -race ./...` no DATA RACE

### Known Limitations

- `internal/cloudflare/transport` and `internal/crowdsec/adapter` have no unit
  tests (require live Cloudflare token / cscli binary; this is pre-existing).
- ModSecurity CF ban, recidive escalation not yet ported — Python `crowdsec-cf-sync`
  continues in reduced mode.
- Lua `bans.json` push remains with Python — nginx enforcement depends on it.

### Upgrade Notes

1. Update `EnvironmentFile` in the systemd unit to point to your env file.
2. If using `CF_SYNC_API_TOKEN` inline, optionally migrate to `CF_SYNC_API_TOKEN_FILE`
   for improved secret hygiene.
3. Set `SECURITY_AUTOMATION_INITIAL_ADMIN_PASSWORD` in env file for first-boot
   bootstrap; it is ignored on subsequent starts.
4. Ensure `LogsDirectory=security-automation` is present in the systemd unit
   (it is in `deployments/systemd/cf-sync.service`).
```
